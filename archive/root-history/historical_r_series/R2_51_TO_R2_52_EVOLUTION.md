# R2.51 → R2.52 Evolution

R2.51 crossed direct helper/caller boundaries inside one Python module. Its strongest remaining representational counterexample was repository topology: the causal chain could cross imports, while the solver still reasoned over a single parsed module and could not coordinate an exact repair across files.

R2.52 closes that counterexample for a bounded static repository setting. `RepositorySnapshot` makes the repository an immutable input object; `RepositoryFactGraph` binds Python files to opaque module/function/symbol nodes, resolves absolute direct `from ... import ...` edges, and carries argument/return `FLOW` plus materialized `FLOW*` across modules. Query induction stays identifier-invariant. All learned edit macros are localized once against the same pre-edit repository graph and then committed together into a new snapshot, so an edit in one file cannot erase localization evidence needed for another file.

The heldout family requires the exact three-macro repair in three distinct files. Demonstrations use three files with shallow cross-module structure; heldout repositories use 5–6 files and call depth 4–5 with opaque identifiers and relay modules. R2.51 applied independently per file scores 0/6, and global syntax application scores 0/6. R2.52 selects the exact three-file transaction in 6/6 episodes, with zero false accepts, after observing at most 6 of 2,401 tests. The target oracle is generated independently of the R2.52 solver, preventing the solver from grading itself.

Two architecture defects were exposed during construction rather than hidden by larger timeouts. First, trace enumeration at depth eight made frozen evaluation exceed the local execution budget even though CEGIS itself was fast. Profiling showed the useful query length was at most six and `FLOW*` already summarized deeper reachability, so the trace bound was reduced to six and per-node traces were cached. Second, target generation initially risked self-confirmation; the final benchmark constructs targets directly from the generator instead of invoking the R2.52 solver. The frozen benchmark then fell to roughly single-digit seconds locally without relaxing correctness gates.

The next falsifiable boundary is real Python repository semantics: packages, relative imports, methods/classes, closures, recursion, higher-order/dynamic dispatch and external dependencies, followed by larger public repositories, noisy/flaky tests and filesystem/VCS transactions with rollback under partial write failure.
