# F v0.8 Durable Effect Journal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a content-addressed durable executor-acknowledgement journal so F can recover the crash window between external acknowledgement and local transaction finalization without replaying the external effect.

**Architecture:** Introduce a focused `EngineeringEffectJournal` protocol that stores immutable application and rollback acknowledgements as observation-only facts. The existing effects ledger keeps intent/commit/completion authority; the control plane composes journal + effects and requires acknowledgement-backed finalization. Unified state schema advances to control compatibility v0.7.0.

**Tech Stack:** Python dataclasses/enums, existing `canonical_digest`, canonical F ledgers, pytest, GitHub Actions CPython 3.11/3.13.

**Spec:** `docs/superpowers/specs/2026-08-31-f-v0.8-durable-effect-journal-design.md`

## Global Constraints

- No distributed exactly-once claim; executor idempotency/authenticity remains an external integration contract.
- Journal authority is exactly `observation_only`.
- Application commit authority remains `mutation_scope_only`.
- Rollback completion authority remains `recovery_scope_only`.
- Terminal engineering authority remains `candidate_only`.
- Every production behavior change must have a failing RED test first.
- Restore and key rebinding are fail-closed.
- Acceptance requires Part V and Refoundation Epoch 0 on CPython 3.11 and 3.13 against the current PR merge-ref.
